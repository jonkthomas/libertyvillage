## Effective eligibility at the instant of weekly roundup submission

A local news/update item qualifies only when a substantive, independently verified source **publication/announcement timestamp** is in the rolling interval `[submit instant − 7×24h, submit instant]` UTC. The timestamp is tied to the captured source passage, not a model claim, generic page last-modified header or extraction time. A substantive later update to an old page may qualify only if that new development itself has a verified timestamp inside the interval and a captured supporting passage. Its visible wording must state the actual event/update date, not mislabel last week's item as newly announced this ISO week.

An upcoming neighbourhood event, routine closure or non-controversial civic item qualifies if its source explicitly verifies a start date/time in `[submit instant, submit instant + 14×24h)` UTC and it has not concluded, **regardless of how long ago it was announced**. Source publication date may be older than seven days or absent on a current official event page, provided a substantive, currently reachable official/primary source OR two independent substantive publishers explicitly support the event date, location and facts. A model's date inference, stale search snippet, undated event, or generic city-wide listing with no Liberty Village venue/impact is insufficient. If start date is just a calendar date (no time), store the source's stated local date with `America/Toronto` timezone and accept only when that entire local date falls in the 14-day window; do not manufacture precise hours. An already-started event is not called upcoming; a closure with a future independently dated start is eligible. Re-fetch immediately before submit and revalidate passage, date, location, risk and duplication; changed or unreachable evidence is withheld for rebuild. A past event whose venue date already ended is never resurrected by a recent article.

The roundup itself is still identified and counted by its ISO **publication** week; eligible source/event dates may cross its Monday boundary. The deterministic lowercase week slug, one-roundup-per-target/week fence and same-week smoke deadline do not change. Every item cites its own direct source URL and says what that source actually reports; do not describe old announcements as breaking news. One qualifying item may yield the clearly labelled single-item weekly update; zero after these broader windows still yields no post and a reasoned `WEEKLY_NEWS_MISSED` only when the week deadline passes. News crime, elections, safety controversy and risky development applications remain human-only even if in-window; daily news cap and existing publish bar stay unchanged.

## Implementation and acceptance delta

In `validateRoundupItem`/`validateRoundupPack` choose one deterministic category (`news-update` or `upcoming-event`) and prove its corresponding window with verified evidence fields before acceptance. Never let a weak event timestamp waive news source quality, or a recent article waive an already-concluded event. `planRoundup`/submit must use the same submitted `now` and rerun temporal and source validation on the final pack; idempotent replay preserves original context and never mints a different week slug. Tests: news at 6d23h passes / 7d+1s fails; event +13d23h passes even if first announced 21d ago / +14d boundary fails; unknown date, ended event, city-wide no-LV-location, risky election/crime and source swap fail/hold; one honest valid item counts, zero does not. Use an actually verified current-week or upcoming LV source for live staging positive proof if available. Dated local fixtures exercise positive code path but are not a claimed live roundup.
