# Cadence missed-alert start week — bounded correction (2026-09-29)

The weekly-blog and weekly-roundup runner each read `CADENCE_START_ISO_WEEK=YYYY-MM-DD` from the target-specific runner environment (UTC Monday, validated strictly); it sets only the first ISO week eligible for missed-week deadline evaluation, not publication or timer activation. For every run, skip the immediate previous week and every older catch-up week if its Monday is before this bound; keep the existing four-week cap, row-qualified older-week catch-up, idempotent alert keys, current-week no-alert rule and content gate unchanged. If the setting is absent, default the bound to **that run's current UTC ISO Monday**, so no earlier week is retrospectively declared missed; an invalid value fails closed before attempting content. Without an explicitly configured fixed week, past-week missed alerts will stay suppressed on every future run, so John must set the value in the correct target-specific environment when activating production timers; staging can configure its own value independently. This correction neither adds a DB migration nor changes production configuration/timers, and it does not guarantee replay of a fully dead older week with no cadence rows beyond the immediate previous week. Tests must prove a first run ignores its pre-start previous week, a fully dead configured active previous week still emits one deduplicated pair, older weeks before the bound are skipped, missing/invalid settings behave as above, and staging/production settings cannot be interchanged.
