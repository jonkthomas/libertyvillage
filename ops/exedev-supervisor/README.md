# exe.dev supervisor installation and cutover

The complete supervisor change must be merged to both `main` and `staging` before installation or cutover. The service executable and install assets come from `main`; every run checks out `staging` and executes the supervisor lint/tests and trusted SEO refresh there. A one-branch rollout cannot run safely and `install.sh` refuses it.

1. Confirm `scripts/supervisor/cli.mjs`, `scripts/automation/promotion-control.mjs`, `ops/exedev-supervisor/refresh-seo.sh`, and the `test:supervisor` package script exist on both remote branches.
2. Run `install.sh` as `exedev`. `/etc/lv-supervisor.env` intentionally contains no secrets and stays `root:exedev` mode `0640`, so both systemd and the operator-run health check can read it while only root can modify it. Keep its `LV_WEEKLY_OWNER=gha` value and the repository variable at `gha` while validating.
3. Configure the host-only Google credential referenced by `LV_GCP_CREDENTIALS_PATH`; the example points to the ignored main-checkout file because secrets are never copied into the staging worktree or added to git. It must be an exedev-owned, non-symlink regular file at mode `0600`. GitHub access is different: exe.dev's internal proxy injects the attached GitHub App authentication, so there is no GitHub token, credential file, helper, or `gh` config. `LV_EXE_GITHUB_PROXY_AUTH=true` is accepted only with `GITHUB_API_URL` using HTTPS on the exact `github.int.exe.xyz` host; all other shared-client use still requires `GH_TOKEN` or `GITHUB_TOKEN`. Run `health-smoke.sh`. It recreates the service's tokenless environment, confirms the exact repository scope through `gh repo view`, raw and `gh` REST calls, and the exact internal git remote, executes the trusted SEO refresh, and runs pi against the real agent directory inside the service sandbox.
4. Set the repository and VM owner values to `exedev` only after the smoke passes. During the pilot, either `LV_WEEKLY_OWNER=exedev` or `LV_PROMOTION_ENABLED=false` disables both promotion entry paths, so no promotion dispatch, staging-to-main PR, or main merge can start.
5. Recovery is isolated per ledger row and parks a permanently failing row after three attempts so later runs do not retry its GitHub calls forever. To retry a parked row, stop the supervisor service before `node scripts/supervisor/cli.mjs repair`. Repair refuses a live owner/ledger lease, takes the ledger write lock, preserves a unique backup and the original diagnostic, resets the bounded attempt counter, and queues failed rows for isolated reconciliation.

Rollback uses `disable-rollback.sh`; repository variable changes remain an explicit operator action.
