# exe.dev supervisor installation and cutover

The complete supervisor change must be merged to both `main` and `staging` before installation or cutover. The service executable and install assets come from `main`; every run checks out `staging` and executes the supervisor lint/tests there. A one-branch rollout cannot run safely and `install.sh` refuses it.

1. Confirm `scripts/supervisor/cli.mjs`, `scripts/automation/promotion-control.mjs`, `scripts/automation/weekly-owner.mjs`, `ops/exedev-supervisor/owner.txt`, `data/topic-queue.json`, `scripts/prompts/sections/03-blog-generation.md`, and the `test:supervisor` package script exist on both remote branches.
2. Run `install.sh` as `exedev`. `/etc/lv-supervisor.env` intentionally contains no secrets and stays `root:exedev` mode `0640`, so both systemd and the operator-run health check can read it while only root can modify it. Keep its `LV_WEEKLY_OWNER=gha` value while validating. The protected, committed `ops/exedev-supervisor/owner.txt` is the canonical GitHub-side owner; repository Actions variables are not used for ownership.
3. No Google, GSC, or GA4 credential is required by the staging supervisor. The selected topic is read from the trusted weekly `data/topic-queue.json`, which remains GitHub Actions-owned and is populated from GSC and SerpApi signals. Pi receives that queue, the selected entry's source/rationale, local businesses and posts, and `scripts/prompts/sections/03-blog-generation.md` as grounding. After upgrading an earlier pilot install, delete the now-unused `/var/lib/lv-supervisor/context/` directory and any old credential at either `/home/exedev/libertyvillage/gcp-credentials.json` or `~/.config/lv-supervisor/gcp-credentials.json`. exe.dev's internal proxy injects the attached GitHub App authentication, so there is no GitHub token, credential file, helper, or `gh` config. `LV_EXE_GITHUB_PROXY_AUTH=true` is accepted only with `GITHUB_API_URL` using HTTPS on the exact `github.int.exe.xyz` host; all other shared-client use still requires `GH_TOKEN` or `GITHUB_TOKEN`. Run `health-smoke.sh`. It recreates the service's tokenless environment, confirms the exact repository scope through `gh repo view`, raw and `gh` REST calls, the exact internal git remote, the queue and selected-entry schema on both trusted branches, and pi against the real agent directory inside the service sandbox.
4. Cut over with an auditable PR that changes only `ops/exedev-supervisor/owner.txt` from `gha` to `exedev` and lands on both `staging` and protected `main`. Once `main` changes, GHA generation and promotion stop. Then change `/etc/lv-supervisor.env` from `LV_WEEKLY_OWNER=gha` to `LV_WEEKLY_OWNER=exedev` and rerun `health-smoke.sh`. The interval between those operations deliberately creates a no-run gap. It can never create a dual-run gap because every host run first performs a read-only fetch, strictly parses `owner.txt` from both `origin/main` and `origin/staging`, and requires both values to equal the VM env before acquiring a run lease. A stale `supervisor-local` owner file cannot deadlock cutover or authorize work. `LV_PROMOTION_ENABLED=false` remains an explicit emergency stop for both promotion entry paths.
5. Recovery is isolated per ledger row and parks a permanently failing row after three attempts so later runs do not retry its GitHub calls forever. To retry a parked row, stop the supervisor service before `node scripts/supervisor/cli.mjs repair`. Repair refuses a live owner/ledger lease, takes the ledger write lock, preserves a unique backup and the original diagnostic, resets the bounded attempt counter, and queues failed rows for isolated reconciliation.

Rollback uses `disable-rollback.sh`. It first disables the VM timers. Then merge an auditable `owner.txt` PR changing `exedev` back to `gha` on `staging` and protected `main`, change the VM env back to `gha`, and rerun the smoke check. GHA may resume only after the protected main change while the VM stays disabled, preserving the same no-run—not dual-run—gap. No Actions variable mutation is part of cutover or rollback.
